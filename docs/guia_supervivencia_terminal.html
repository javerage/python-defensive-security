2. Entorno Virtual Aislado (venv)

Paso Windows (PowerShell) Linux / macOS
1. Crear python -m venv .venv python3 -m venv .venv
2. Activar .venv\Scripts\Activate.ps1 source .venv/bin/activate
¿Activo? ✔ Tu prompt debe iniciar con: (.venv)
3. Salir deactivate deactivate
Desbloqueo Si Windows bloquea scripts:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

🥷 4 Atajos Ninja de Productividad

  • Tab : Autocompleta nombres de archivo y carpetas (¡evita errores de dedo!).
  • ↑ / ↓ : Historial de comandos (no vuelvas a escribir comandos largos).
  • Ctrl + C : Abortar / Detener de emergencia cualquier programa trabado.
  • Ctrl + L : Limpiar la pantalla instantáneamente en bash/zsh.

🩺 Diagnóstico en 1-Clic

¿Dudas si tu entorno está bien configurado? Ejecuta el verificador oficial:

Revisa automáticamente: versión de Python, aislamiento de .venv, permisos de PowerShell y sistema operativo.

⚠️ Semáforo de Contingencias: ¿Qué hacer si algo sale mal?

Aparecen los caracteres >>> Estás dentro de la consola interactiva (REPL) de Python, no en la terminal del sistema. Sal de ahí escribiendo exit() y presiona Enter.
Error: File ... cannot be loaded (PSSecurityException) Windows bloquea scripts por seguridad. Ejecuta en PowerShell: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass y vuelve a activar el venv.
VS Code dice "WSL" o "Ubuntu" estando en Windows VS Code se conectó a una máquina virtual de Linux por error. Cierra esa ventana y en tu terminal selecciona Windows PowerShell como perfil predeterminado.
El prompt no muestra (.venv) No has activado tu entorno virtual. Ejecuta .venv\Scripts\Activate.ps1 (Windows) o source .venv/bin/activate (Linux/macOS) antes de correr tus scripts.
