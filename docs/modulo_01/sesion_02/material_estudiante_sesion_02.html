2. Fundamentos Conceptuales de la Sesión

En Python, una variable es un nombre que apunta a un valor en memoria. Cada valor tiene un tipo: Python lo revisa antes de operar y no mezcla tipos sin tu permiso (por eso sumar texto con números produce un error en vez de un resultado corrupto).

Cómo nace una variable en Python (en clase, sin evaluar)

En Python asignas un valor sin declarar antes el tipo:

failed_attempts = 5 print(type(failed_attempts)) # Muestra: <class 'int'>

El nombre referencia un valor y el valor tiene el tipo. La función type() es solo una linterna para mirarlo; no es un tema evaluado.

Lenguaje Cómo se escribe Qué significa
Python failed_attempts = 5 Asignas sin declarar el tipo.
C / Java int failed_attempts = 5; Declaras el tipo antes de asignar.
JavaScript let failed_attempts = 5; let declara el enlace, pero no escribe el tipo del valor.
📌 Tres precisiones y nada más

Dinámico pero fuerte: no declaras tipos, pero Python tampoco mezcla automáticamente texto y números en operaciones incompatibles (por eso existe el TypeError de la sección 5).

Un solo int: Python 3 usa un entero de precisión arbitraria; no tiene byte, short, int y long de distinto rango como otros lenguajes (esos nombres, y TINYINT o SMALLINT, los verás en bases de datos). No es memoria infinita: el límite práctico es la memoria disponible.

Alcance de hoy: en esta sesión trabajamos str, int, float y bool. Python posee otros tipos incorporados y colecciones que se estudiarán después; estos cuatro no son los únicos.

Tipo de Dato Representación y Sintaxis Rol en Ciberseguridad Defensiva Ejemplo en Código (PEP 8)
str (String) Texto entre comillas simples o dobles. Nombres, identificadores y todo lo que devuelve input(). operator_name = "Alex Rivera"
int (Integer) Números enteros sin decimales. Conteos: laboratorios completados, intentos, turnos. completed_labs = 4
float (Float) Números con decimales. Mediciones: promedios de horas, porcentajes, tiempos. hours_per_lab = 2.5
bool (Boolean) Solo True o False. Decisiones: ¿alcanzó el requisito? ¿avanza a la simulación? ready_for_next = True
💡 La ruta de tus datos: texto → número → resultado

Todo lo que escribes en input() llega como texto (str), incluso si tecleas 4. Para Python, ese 4 entre comillas no es una cantidad: es un carácter.

Las funciones int() y float() transforman ese texto en número cuando el texto ya es numérico. No corrigen ni adivinan: si el texto no es un número (por ejemplo 'cuatro'), el programa se interrumpe con ValueError. Controlar ese caso con try/except lo verás en una sesión posterior; hoy basta con ingresar números.

4. Reto Práctico: Perfil de Operador (25 minutos)

🎯 Historia: revisar experiencia antes de la simulación (perfil_operador.py)

Formas parte del equipo que coordina el entrenamiento de nuevos operadores de seguridad. Antes de permitir que un operador participe en una simulación de incidentes, debes revisar su experiencia práctica. Para ello registras su nombre, cuántos laboratorios introductorios completó y el promedio de horas que dedicó a cada uno. Al multiplicar los laboratorios completados por el promedio de horas, obtienes una estimación de sus horas totales de práctica. El programa de entrenamiento establece un mínimo de 10 horas antes de avanzar a la siguiente simulación. Finalmente, muestras un resumen que permite identificar al operador, revisar su progreso y saber si alcanzó ese requisito.

Los 5 pasos (en este orden):

  1. Entrada de texto: pide los 3 datos con input() (operator_name identifica de quién es el progreso; raw_completed_labs y raw_hours_per_lab traen sus prácticas y su dedicación).
  2. Conversión: completed_labs = int(raw_completed_labs) (prácticas terminadas) y hours_per_lab = float(raw_hours_per_lab) (promedio de dedicación).
  3. Cálculo: total_practice_hours = completed_labs * hours_per_lab (la multiplicación estima la práctica acumulada).
  4. Decisión: ready_for_next = total_practice_hours >= 10.0 (verifica la regla explícita del programa; True alcanzó el requisito, False aún no — el programa no autoriza por sí solo).
  5. Comunicación: imprime el encabezado y las cinco líneas de datos con print() (evidencia legible para revisar la decisión).

Tu archivo perfil_operador.py (complétalo):

# STEP 1: Text input — input() ALWAYS returns str operator_name = input("Escribe el nombre del operador: ") raw_completed_labs = input("Escribe cuantos laboratorios completo: ") raw_hours_per_lab = input("Escribe el promedio de horas por laboratorio: ") # STEP 2: Conversion — TODO: convierte el texto en números completed_labs = int(raw_completed_labs) hours_per_lab = float(raw_hours_per_lab) # STEP 3: Calculation — TODO: una sola métrica total_practice_hours = completed_labs * hours_per_lab # STEP 4: Decision — TODO: verifica la regla de 10.0 horas (¿alcanzó el requisito?) ready_for_next = total_practice_hours >= 10.0 # STEP 5: Communication — resumen simple y legible print("--- Resumen del operador ---") print(f"Nombre: {operator_name}") print(f"Laboratorios completados: {completed_labs}") print(f"Horas por laboratorio: {hours_per_lab}") print(f"Horas totales de practica: {total_practice_hours}") print(f"Listo para la siguiente practica: {ready_for_next}")

5. Clínica de Errores: Lee el Mensaje

Los errores te dicen exactamente qué pasó. Estos son los dos de esta sesión:

🚨 Error 1: TypeError por operar con texto sin convertir
Traceback (most recent call last): File "perfil_operador.py", line 12, in <module> total_practice_hours = raw_completed_labs * hours_per_lab TypeError: can't multiply sequence by non-int of type 'float'
Qué pasó:

raw_completed_labs es el texto que devolvió input(). Python no multiplica texto por decimales sin tu permiso.

Cómo se corrige:

Convierte primero y opera después: completed_labs = int(raw_completed_labs) y luego completed_labs * hours_per_lab.

⚠️ Error 2: ValueError por texto que no es número
Traceback (most recent call last): File "perfil_operador.py", line 10, in <module> completed_labs = int(raw_completed_labs) ValueError: invalid literal for int() with base 10: 'cuatro'
Qué pasó:

int() solo transforma texto que ya es numérico. 'cuatro', '2,5' o una entrada vacía no lo son, así que el programa se interrumpe. La conversión no valida ni corrige.

Cómo se corrige hoy:

Vuelve a ejecutar con ↑ e ingresa solo números (4, 2.5). Controlar este caso con try/except lo aprenderás en una sesión posterior.

🎯 Historia: organizar observaciones para revisión humana (analisis_acceso.py)

Actúas como el analista responsable de organizar observaciones iniciales para una revisión humana. El punto de partida es una alerta local de práctica sobre intentos fallidos de acceso. Registras el identificador de la cuenta del caso (account_id), cuántos eventos ocurrieron (failed_attempts) y la ventana temporal observada (observation_minutes). Calcular la frecuencia importa porque 12 intentos en 3 minutos no representan el mismo ritmo que 12 intentos durante una ventana mucho mayor. Dos reglas didácticas independientes generan dos señales: volumen (many_failed_attempts, con >= 5) y ritmo (rapid_attempts, con >= 2.0). True solo indica que se cumple la regla correspondiente; no son estándares universales ni prueban un ataque. Tu resumen le sirve a la persona responsable de revisar el caso para decidir si necesita recopilar más información o continuar una investigación humana. Crea manualmente analisis_acceso.py en tu proyecto personal, con código lineal y nombres técnicos en inglés (mensajes en español).

Los 5 pasos (en este orden):

  1. Entrada de texto: pide los 3 datos con input() (account_id identifica la cuenta del caso; raw_failed_attempts y raw_observation_minutes traen eventos y ventana).
  2. Conversión: failed_attempts = int(raw_failed_attempts) (cuenta eventos) y observation_minutes = float(raw_observation_minutes) (delimita la ventana).
  3. Cálculo: attempts_per_minute = failed_attempts / observation_minutes (el ritmo permite comparar ventanas distintas).
  4. Decisiones: many_failed_attempts = failed_attempts >= 5 (volumen) y rapid_attempts = attempts_per_minute >= 2.0 (ritmo). Son reglas didácticas independientes; True solo indica que se cumple la regla. Sin and, sin funciones, sin colecciones, sin try/except, sin if.
  5. Comunicación: imprime el resumen legible para quien revisa el caso.

--- Resumen de triage --- Cuenta: admin-local Intentos fallidos: 12 Minutos observados: 3.0 Intentos por minuto: 4.0 Muchos intentos fallidos: True Intentos rapidos: True
⚠️ Propósito real y límites

El reporte organiza observaciones iniciales para la revisión humana: no confirma un ataque, no bloquea cuentas y no sustituye la investigación.

Usa minutos mayores que cero (como el 3 del ejemplo): si observation_minutes vale 0 o 0.0, la división produce ZeroDivisionError. Controlar ese error y otras entradas inválidas queda para la sesión de manejo de errores posterior.
