2. Fundamentos Conceptuales de la Sesión

Una lista guarda varios valores juntos conservando su orden y permitiendo duplicados. En sesiones anteriores trabajaste con un valor a la vez; hoy guardas cinco eventos en una sola variable y los procesas con un pipeline: cada operación transforma la lista y una impresión inmediata prueba qué cambió antes de seguir. Nada avanza a ciegas.

Cómo procesa Python una lista (en clase, sin evaluar nada más)

Las posiciones empiezan en 0: el primer evento vive en [0]. Cada operación devuelve algo distinto:

event_log.append("WARNING: reintento local programado") error_count = event_log.count("ERROR: disco lleno en el laboratorio") error_position = event_log.index("ERROR: disco lleno en el laboratorio")

append agrega al final y no devuelve nada útil; count devuelve cuántos coinciden (aquí 1) sin borrar; index devuelve la posición del primer coincidente (aquí 3).

event_log.remove("INFO: respaldo local completo") event_log.sort() recent_events = event_log[0:3]

remove borra por valor el primer coincidente; sort ordena la misma lista y devuelve None (por eso se llama solo, nunca se asigna); el rebanado [0:3] copia las posiciones 0, 1 y 2 en una lista nueva sin tocar el original.

📌 Tres precisiones y nada más

Cada operación devuelve algo distinto: append nada útil, count cuántos, index dónde, sort None. Si escribes ordered_log = event_log.sort(), después ves None sin ningún mensaje de error (verás este caso en la sección 5).

Operaciones de hoy, nada más: creación, índices, slicing, len() y los métodos append, count, index, remove y sort. El desempaquetado y las matrices (listas anidadas) solo se mencionan: no se usan ni se evalúan en esta sesión.

Alcance de hoy: listas de texto en memoria con impresiones intermedias. Las etiquetas INFO/WARNING/ERROR son didácticas del laboratorio, no estándares universales. Los diccionarios llegan en la Sesión 07 y los bucles en la Sesión 09.

in es un operador de pertenencia, no un método: no lleva paréntesis propios y no modifica la lista. Contraste clave: str.find() ante un valor ausente devuelve -1, mientras list.index() ante un valor ausente interrumpe con ValueError. Por eso primero se pregunta sin romper y el pipeline usa index() solo sobre un valor conocido del fixture.

target_event = "ERROR: disco lleno en el laboratorio" print(target_event in event_log) # True print("ERROR: inexistente" in event_log) # False

Este ejemplo responde a la pregunta “¿existe este evento?”: el primer caso está presente (True) y el segundo está ausente (False). in no es un séptimo paso evaluado: no añade línea al resumen ni cambia las salidas. Solo permite preguntar primero sin romper.

5. Clínica de Errores: Lee el Mensaje

En Python 3.13, las trazas de error (Tracebacks) señalan la línea y columna exacta de la falla con caracteres ^^^^^. Analiza y resuelve los 2 errores típicos de esta sesión:

🚨 Error 1: IndexError por pedir una posición inexistente
Traza real de Python 3.13event_pipeline.py
File "event_pipeline.py", line 40, in <module> sixth_event = event_log[6] ~~~~~~~~~^^^ IndexError: list index out of range
Causa raíz:

La lista tiene 5 elementos (posiciones 0 a 4). Python numera desde 0: la última posición válida es el tamaño menos uno.

Corrección:

Pide una posición dentro del rango o comprueba el tamaño con len() antes.

⚠️ Error 2: asignar sort() y ver None en silencio (sin traza)
Salida sin error… pero con Noneevent_pipeline.py
ordered_log = event_log.sort() print(ordered_log) # muestra None
Causa raíz:

sort ordena la misma lista y devuelve None a propósito; la variable guarda ese None.

Corrección:

Llama event_log.sort() solo en su línea y sigue usando event_log.

📌 Nota documentada: ValueError (no es un tercer error provocado)

Si index() o remove() reciben un texto que no está letra por letra en la lista, Python interrumpe con ValueError: '...' is not in list. Contraste con S03: text.find(value) ante un texto ausente devuelve -1, mientras list.index(value) ante un valor ausente interrumpe con ValueError. La corrección es copiar el texto exacto de los materiales. No se usa try/except en esta sesión; en clase solo se provocan los dos errores de arriba.
