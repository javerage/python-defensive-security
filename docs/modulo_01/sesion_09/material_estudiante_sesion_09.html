2. Fundamentos Conceptuales de la Sesión

Un ciclo repite una acción sobre cada dato sin copiar la línea 20 veces. El for visita cada evento de la lista y termina solo cuando se acaban los datos. El while repite mientras una condición sea verdadera y necesita avanzar su contador en cada vuelta. En la Sesión 08 agrupaste con sets sin bucles; hoy cuentas los mismos 20 eventos dos veces, una con cada ciclo, y ambos deben dar 6.

Cómo recorre Python con for y while (en clase, sin evaluar nada más)

El for visita cada elemento sin índices:

for_count = 0 for event in event_log: if event == "ERROR": for_count = for_count + 1

Con los 20 eventos de la práctica, for_count termina en 6. El ciclo se detiene solo: no hay condición que olvidar.

El while necesita inicio, condición y avance visibles:

while_count = 0 index = 0 while index < len(event_log): if event_log[index] == "ERROR": while_count = while_count + 1 index = index + 1

Con los mismos 20 eventos, while_count también termina en 6 y index termina en 20. Si falta index = index + 1, el ciclo nunca avanza y nunca termina.

La coincidencia se verifica con una comparación directa:

both_match = for_count == while_count

both_match es True porque ambos cuentan 6. Esa es la prueba de que las dos versiones recorrieron los mismos 20.

📌 Tres precisiones y nada más

for frente a while: for termina solo al agotar la lista (20 visitas); while termina cuando index < 20 deja de cumplirse. Si el avance falta, el while repite la misma posición sin fin (verás este caso en la sección 5).

Ciclos de hoy, nada más: for sobre lista, while con contador, len(), range() solo como lectura y comparación de totales. Los ciclos anidados llegan en la Sesión 10; hoy un solo nivel.

Alcance de hoy: 20 datos sintéticos del laboratorio con 6 ERROR. Las etiquetas son didácticas del laboratorio, no estándares universales. Sin funciones, sin archivos, sin red.

CicloRegla válida / inválidaEjemplo de la sesión
forVálido: visita cada elemento y termina solo. Inválido: modificar el contador a mano.for event in event_log → 20 visitas, 6 conteos.
whileVálido: inicio + condición + avance. Inválido: condición sin avance (bucle infinito).while index < 20 con index += 1 → termina en 20.

range / lenVálido: len(event_log) es 20. Inválido: número fijo que se desactualiza.while index < len(event_log) sigue válido si la lista crece.
💡 La cinta transportadora y el torniquete

Piensa en una cinta con 20 cajas: el for revisa cada caja que pasa y la cinta se detiene sola al final. El while es un torniquete con contador: deja pasar mientras queden cajas y cada paso suma uno.

Si el torniquete no suma, la misma caja pasa sin fin: ese es el bucle infinito que hoy aprendes a evitar.

5. Clínica de Errores: Lee el Mensaje

En Python 3.13, las trazas de error (Tracebacks) señalan la línea y columna exacta de la falla con caracteres ^^^^^. Analiza y resuelve los 2 errores típicos de esta sesión:

🚨 Error 1: IndexError por avanzar de más en while
Traza real de Python 3.13event_loop.py
File "event_loop.py", line 31, in <module> if event_log[index] == "ERROR": ~~~~~~~~~^^^^^^^ IndexError: list index out of range
Causa raíz:

La condición permite index == 20: la lista llega hasta 19 y Python señala los corchetes.

Corrección:

Mantén while index < len(event_log) con avance de uno por vuelta.

⚠️ Error 2: while sin avance que se cuelga en silencio (sin traza)
Programa que nunca termina…event_loop.py
index = 0 while index < len(event_log): if event_log[index] == "ERROR": while_count = while_count + 1 # falta index = index + 1: repite la posición 0 sin fin
Causa raíz:

Sin avance, la condición siempre es verdadera: el programa repite la misma posición sin mostrar error.

Corrección:

Agrega index = index + 1 al final del cuerpo y cancela el cuelgue con Ctrl + C.
