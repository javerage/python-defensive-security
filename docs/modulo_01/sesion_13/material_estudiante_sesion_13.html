2. Fundamentos Conceptuales de la Sesión

Un bloque vigilado separa el intento del remedio: try intenta la revisión, cada except captura un tipo de error, else corre solo si nada falló y finally siempre deja constancia en la bitácora. Una excepción propia es un sello nuevo (ReviewLevelError) que marcas con raise cuando el nivel no pertenece al laboratorio. El registro (logging) guarda cada captura en defense.log para que la consola nunca muestre trazas crudas al usuario. En la Sesión 12 el dato perfecto bastaba; hoy el dato imperfecto también entrega reporte.

Cómo vigila Python (en clase, sin evaluar nada más)

La guardia envuelve las 3 revisiones heredadas de la Sesión 12:

def safe_review(source_name, level): """Guard one inherited review.""" try: events = load_source(source_name) clean_level = validate_level(level) total, verdict = review_events(events, level=clean_level) except FileNotFoundError as exc: logging.warning(f"captured missing source: {exc}") total, verdict = 0, "Rutina local" except ReviewLevelError as exc: logging.warning(f"captured invalid level: {exc}") total, verdict = 0, "Rutina local" else: logging.info(f"reviewed {source_name} level {clean_level}: {total}") finally: logging.info(f"finished task for {source_name} level {level}") return total, verdict

Con los 20 eventos de la práctica, safe_review("local_events", "ERROR") responde por else con (6, "Revisión prioritaria"). Con safe_review("missing_source", "CRITICAL") la carga falla primero y el except FileNotFoundError responde con (0, "Rutina local") sin traza cruda.

La excepción propia nace de una sola subclase permitida:

class ReviewLevelError(Exception): """Raised when a review level is unknown to the local lab."""
📌 Tres precisiones y nada más

Cuatro ramas: try intenta, cada except captura un tipo, else corre solo si nada falló, finally siempre registra.

Excepción propia: ReviewLevelError marca niveles desconocidos; se lanza con raise y se captura por su tipo, nunca con un except desnudo.

Alcance de hoy: 20 datos sintéticos con 6 ERROR y 5 WARNING, 3 tareas vigiladas y 1 error capturado en defense.log.

💡 La central de alarmas con bitácora

Piensa en una central de alarmas: cada sensor (try) puede fallar, la operadora captura cada incidente por su tipo (except), el parte de calma solo se firma si nada sonó (else) y la bitácora se escribe pase lo que pase (finally).

Tu programa hace lo mismo: las capturas viajan a defense.log y los veredictos tranquilos viajan a la consola.

5. Clínica de Errores: Lee el Mensaje

En Python 3.13, las trazas de error (Tracebacks) señalan la línea y columna exacta de la falla con caracteres ^^^^^. Analiza y resuelve los 2 errores típicos de esta sesión:

🚨 Error 1: FileNotFoundError por abrir la fuente sin guardia
Traza real de Python 3.13harden_review.py
File "harden_review.py", line 41, in <module> events = open("daily.log", encoding="utf-8") ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ FileNotFoundError: [Errno 2] No such file or directory: 'daily.log'
Causa raíz:

Pediste una fuente local que no existe y nada la capturó; Python señala la llamada con ^^^^^.

Corrección:

Envuelve la carga en try, captura FileNotFoundError con reporte en español y registra con logging.warning.

⚠️ Error 2: ReviewLevelError que escapa de un except estrecho
Traza real de Python 3.13harden_review.py
File "harden_review.py", line 58, in <module> total, verdict = review_events(events, level="CRITICAL") File "harden_review.py", line 33, in validate_level raise ReviewLevelError(f"unknown review level: {level}") ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ ReviewLevelError: unknown review level: 'CRITICAL'
Causa raíz:

El nivel no pertenece al conjunto conocido y tu único except FileNotFoundError lo dejó escapar.

Corrección:

Agrega except ReviewLevelError por su tipo y registra la captura; nunca uses un except desnudo.
