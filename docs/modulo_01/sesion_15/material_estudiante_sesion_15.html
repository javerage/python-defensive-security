2. Fundamentos Conceptuales de la Sesión

2.1 El objeto Path: direcciones que se razonan, no texto que se concatena

Un Path de pathlib representa una ruta del sistema de archivos como objeto, no como cadena suelta. El operador / une carpetas de forma multiplataforma (PROJECT_ROOT / "datos" / "app.log"), read_text(encoding="utf-8") lee el archivo completo y write_text(datos, encoding="utf-8") lo escribe. La carpeta de destino se garantiza con output_path.parent.mkdir(parents=True, exist_ok=True) antes de escribir.

2.2 Rutas ancladas: el archivo manda, la consola no

Una ruta relativa suelta como "datos/app.log" se resuelve contra el directorio de trabajo de la consola, que cambia con cada cd. La ruta anclada Path(__file__).resolve().parent se resuelve contra la ubicación del propio script, que no cambia. Por eso el programa de hoy funciona ejecutado desde la raíz aunque la consola haya visitado otras carpetas.

2.3 UTF-8 explícito y errores de archivo con try/except

Declarar encoding="utf-8" en cada lectura y escritura evita que Windows y Linux interpreten distinto los mismos bytes. Cuando el fixture falta, read_text lanza FileNotFoundError; el bloque try/except heredado de la Sesión 13 lo captura e imprime un mensaje útil en vez de una traza cruda. Las líneas malformadas (vacías o sin dos puntos) no son errores del programa: se omiten, se cuentan y su motivo viaja al registro con logging.

2.4 Escritura atómica: temporal más renombrar

Escribir directo sobre el archivo final expone mitades si el programa se interrumpe. La escritura atómica escribe primero normalizado.tmp y luego lo renombra sobre normalizado.txt con temp_path.replace(output_path): el renombrar sustituye el archivo de una vez, así que el lector del siguiente turno (el kit/ de la Sesión 14) solo ve archivos terminados.

💡 Analogía de Seguridad Defensiva: El cambio de turno con carpeta sellada

En un centro de operaciones nadie entrega papeles sueltos a medias: el analista saliente mete el reporte terminado en una carpeta, la sella y la deja en la bandeja; el entrante solo toca carpetas selladas. La escritura atómica es esa carpeta sellada: el temporal es la mesa de trabajo y el renombrar es el sello. La ruta anclada es la dirección fija de la bandeja, que no cambia aunque el mensajero venga de otra oficina.

5. Clínica de Errores y Diagnóstico de Tracebacks

En Python 3.13, las trazas de error (Tracebacks) proporcionan indicadores precisos señalando la línea y columna exacta de la falla con caracteres ^^^^^. Analice y resuelva los 2 errores típicos sembrados de esta sesión:

🚨 Error Sembrado 1: Ruta relativa mal resuelta (la consola manda, el archivo no)
PS C:\lab\curso-python-defensivo\docs> python ..\normalize_logs.py Traceback (most recent call last): File "..\normalize_logs.py", line 58, in <module> input_text = Path("datos/app.log").read_text(encoding="utf-8") ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ FileNotFoundError: [Errno 2] No such file or directory: 'datos/app.log'
Causa Raíz Técnica:

La ruta suelta "datos/app.log" se resolvió contra el directorio de trabajo de la consola (docs/), no contra la raíz del proyecto. Python buscó docs/datos/app.log, que no existe. Los ^^^^^ señalan la llamada exacta que intentó abrir el archivo.

Protocolo de Corrección:

1. Ancle la ruta: PROJECT_ROOT = Path(__file__).resolve().parent y INPUT_PATH = PROJECT_ROOT / "datos" / "app.log". 2. Verifique con dir o ls. 3. Vuelva a la raíz con cd y re-ejecute con ↑.

⚠️ Error Sembrado 2: FileNotFoundError al publicar (la carpeta salida/ no existe)
(.venv) PS C:\lab\curso-python-defensivo> python normalize_logs.py Traceback (most recent call last): File "normalize_logs.py", line 74, in main temp_path.write_text(chr(10).join(clean_lines), encoding="utf-8") ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ FileNotFoundError: [Errno 2] No such file or directory: 'salida/normalizado.tmp'
Causa Raíz Técnica:

La escritura atómica intentó crear el temporal dentro de salida/, pero esa carpeta aún no existe en un proyecto recién creado. Ni el temporal ni el renombrar pueden crear carpetas por sí solos. Los ^^^^^ señalan la escritura del temporal.

Protocolo de Corrección:

1. Cree la carpeta antes de escribir: output_path.parent.mkdir(parents=True, exist_ok=True) al inicio de write_atomic. 2. Re-ejecute y confirme que solo queda normalizado.txt sin .tmp residual.
