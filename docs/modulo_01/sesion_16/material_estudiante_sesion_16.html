2. Fundamentos Conceptuales de la Sesión

2.1 JSON y CSV: el mismo evento, dos maletas

Un dict de Python viaja a JSON con json.dumps(records, indent=2, ensure_ascii=False) y regresa con json.loads(content): el archivo conserva los 20 dicts con tipos originales. El CSV solo transporta texto, así que csv.DictWriter escribe encabezados más una fila por evento aceptado, y csv.DictReader devuelve cada fila como dict de cadenas. Regla innegociable de hoy: el CSV llega a dict antes de validar; validar una lista cruda produce ValidationError de tipo model_type.

2.2 logging a archivo: la bitácora del lote

El reporte de consola es para el humano de turno; la bitácora es para la auditoría. Un FileHandler en modo "w" con encoding="utf-8" reinicia proceso.log en cada lote y recibe 6 entradas INFO: (inicio, fixture, validación, demo strict, CSV publicado, prueba CSV→dict). La consola nunca imprime trazas crudas: cada rechazo viaja con motivo en español.

2.3 El primer BaseModel: esquema con type hints

La clase Evento(BaseModel) declara el contrato del evento: event_id: int, level limitado a los tres textos permitidos, message y source no vacíos. Evento.model_validate(raw_item) acepta el dict o lanza ValidationError, que agrupa un error por campo; el programa la captura con try/except y extrae exc.errors()[0] para construir el motivo (campo faltante, tipo invalido o valor no permitido).

2.4 Lax contra strict: el mismo registro, dos veredictos

El modo lax (por defecto) convierte valores compatibles: el registro 15 trae "15" como texto y entra aceptado con event_id == 15. Con strict=True el mismo dict se rechaza porque la conversión ya no se permite. Aclaración obligatoria: Pydantic valida en este límite de entrada; no garantiza los tipos del resto del programa y no sustituye la comprensión de tipos, las pruebas ni el análisis estático.

💡 Analogía de Seguridad Defensiva: La aduana del aeropuerto

En una aduana nadie revisa el avión entero por cada pasajero: cada pasaporte pasa por el lector, que acepta documentos válidos, convierte formatos compatibles (un código con guion a su forma canónica) y rechaza lo demás con un motivo sellado. El modelo Evento es ese lector: el JSON es la fila de pasajeros, el CSV es la lista de admitidos y proceso.log es el libro de la aduana. Y como en la aduana real, el sello solo cubre el control de entrada, no todo el viaje.

5. Clínica de Errores y Diagnóstico de Tracebacks

En Python 3.13, las trazas de error (Tracebacks) proporcionan indicadores precisos señalando la línea y columna exacta de la falla con caracteres ^^^^^. Analice y resuelva los 2 errores típicos sembrados de esta sesión:

🚨 Error Sembrado 1: Campo faltante (el dict llega sin "level")
(.venv) PS C:\lab\curso-python-defensivo> python validate_events.py Traceback (most recent call last): File "validate_events.py", line 96, in main event = Evento.model_validate(raw_item) ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ pydantic_core._pydantic_core.ValidationError: 1 validation error for Evento level Field required [type=missing, input_value={'event_id': 16, ...}, input_type=dict]
Causa Raíz Técnica:

El dict 16 no trae la clave level, obligatoria en el esquema. model_validate lanza ValidationError agrupada por campo; sin try/except la traza cruda interrumpe el lote. Los ^^^^^ señalan la llamada exacta que intentó validar.

Protocolo de Corrección:

1. Envuelva la validación en try/except ValidationError. 2. Extraiga exc.errors()[0] y publique registro 16: campo faltante (level). 3. Re-ejecute con ↑ y confirme 15 + 5 = 20.

⚠️ Error Sembrado 2: Tipo inválido (texto no numérico en "event_id")
(.venv) PS C:\lab\curso-python-defensivo> python validate_events.py Traceback (most recent call last): File "validate_events.py", line 96, in main event = Evento.model_validate(raw_item) ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ pydantic_core._pydantic_core.ValidationError: 1 validation error for Evento event_id Input should be a valid integer, unable to parse string as an integer [type=int_parsing, input_value='sin-numero', input_type=str]
Causa Raíz Técnica:

El dict 17 trae "sin-numero" donde el esquema exige int. Ni el modo lax puede convertir un texto no numérico, así que Pydantic lo rechaza con error int_parsing. Los ^^^^^ señalan la misma frontera: el límite de entrada.

Protocolo de Corrección:

1. Capture la excepción y publique registro 17: tipo invalido (event_id). 2. Contraste con el registro 15 ("15" sí convierte en lax). 3. Re-ejecute con ↑ y confirme el detalle de 5 rechazados.
