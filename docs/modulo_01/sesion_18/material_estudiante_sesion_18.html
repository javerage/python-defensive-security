2. Fundamentos Conceptuales de la Sesión

2.1 La clase es el molde, el objeto es cada hallazgo

Una clase describe la forma (qué guarda y qué sabe hacer cada hallazgo). Un objeto es cada hallazgo construido con datos reales. El constructor __init__ recibe los datos y los guarda en self como atributos públicos (finding_id, level, message, source). Los métodos públicos (summary(), is_critical()) leen self para resumir o clasificar. La etiqueta _label es privada por convención (el guion bajo pide no leerla desde fuera). En esta sesión no hay herencia: un solo molde basta para el tablero local.

2.2 El BaseModel es el mismo molde con esquema que rechaza

La clase manual acepta lo que su __init__ revisa a mano, y deja pasar el id como texto "7" y el mensaje de 200 caracteres. El modelo Finding(BaseModel) declara el esquema con type hints y restricciones: level solo admite el literal INFO/WARNING/ERROR, message exige entre 1 y 140 caracteres (Field), y el modo strict rechaza conversiones ("7" no entra con strict=True). Lo inválido se rechaza con ValidationError que nombra el campo. Pydantic valida en la frontera donde lo colocas; no garantiza el resto del programa ni sustituye las pruebas.

Tabla de correspondencia manual → validado

💡 Analogía de Seguridad Defensiva: El expediente del hallazgo: carpeta manual que se vuelve formulario con sello

La clase manual es una carpeta donde el analista escribe a mano cada hallazgo y lo resume de memoria; el BaseModel es el mismo expediente convertido en formulario con sellos: si el nivel no existe, el mensaje está vacío o excede 140 caracteres, el formulario lo devuelve con el motivo marcado. El expediente no investiga solo: solo guarda y rechaza en la puerta.

5. Clínica de Errores y Diagnóstico de Tracebacks

En Python 3.13, las trazas de error (Tracebacks) proporcionan indicadores precisos señalando la línea y columna exacta de la falla con caracteres ^^^^^. Analice y resuelva los 2 errores típicos sembrados de esta sesión:

🚨 Error Sembrado 1: Atributo mal escrito (mesage en vez de message)
Traceback (most recent call last): File "finding_model.py", line 118, in <module> print(finding.mesage) ^^^^^^^^^^^^^^ AttributeError: 'Finding' object has no attribute 'mesage'. Did you mean: 'message'?
Causa Raíz Técnica:

El objeto no inventa atributos: mesage no existe en el molde y Python sugiere message. Causa tipográfica, no dato roto.

Protocolo de Corrección:

1. Lea la sugerencia Did you mean. 2. Complete con Tab (finding.me + Tab). 3. Re-ejecute con ↑ y confirme el resumen [INFO].

⚠️ Error Sembrado 2: Validación manual débil que Pydantic rechaza (mensaje de 200 caracteres)
Traceback (most recent call last): File "finding_model.py", line 96, in <module> Finding.model_validate(long_record) ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ pydantic_core._pydantic_core.ValidationError: 1 validation error for Finding message: String should have at most 140 characters [type=string_too_long]
Causa Raíz Técnica:

El __init__ manual no puso tope de longitud y dejó pasar el dict; el BaseModel sí lo rechaza (Field max_length=140) con motivo por campo.

Protocolo de Corrección:

1. Acote el mensaje a 140 caracteres antes de validar. 2. Re-ejecute con ↑. 3. Compare: manual acepta, BaseModel rechaza con string_too_long.
